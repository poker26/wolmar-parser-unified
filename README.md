# Wolmar Parser Unified

Система сбора и анализа нумизматических аукционов. Репозиторий объединяет
парсеры, публичный каталог, личную коллекцию, прогнозирование цен,
аналитику торгов и управление длительными задачами.

## Состав системы

- `server.js` — основной Express API и веб-интерфейс на порту `3001`;
- `public/` — пользовательский и административный интерфейсы;
- `catalog/` — построение, нормализация и сопоставление каталога монет;
- `temporal/` — устойчивые workflow парсинга и пересчёта прогнозов;
- `analytics-service/` — отдельный сервис аналитики на порту `3002`;
- `scripts/` — исследовательские и эксплуатационные сценарии парсинга;
- `BrowserProxy` — отслеживаемый gitlink внешнего браузерного прокси.

Боевая аналитика собирается только из `analytics-service/`. Отдельный репозиторий
`wolmar-analysis` (бывшая папка `wolmar-analytics-clean`) остался архивом
дореди­зайнной версии и в рабочем дереве больше не лежит.

Основной источник данных — PostgreSQL. Дополнительные компоненты используют
Temporal и объектное хранилище, когда соответствующие переменные окружения
настроены.

## Каноническая рабочая копия

Каноническим checkout является корень этого репозитория. Не используйте
вложенную папку `wolmar-parser-unified/`: это локальная устаревшая копия,
которая исключена из Git.

Активная разработка каталога ведётся в ветке `coin-catalog`. Перед переносом
изменений в `main` следует отдельно проверить незакоммиченные файлы каталога,
Temporal и интерфейса.

## Установка и запуск

```bash
npm install
npm start
```

Для разработки с автоматическим перезапуском:

```bash
npm run dev
```

Конфигурация читается из `.env`. За основу следует брать
`config.example.js`; рабочие секреты не нужно добавлять в новые файлы или
выводить в логи.

## Проверка изменений

Быстрая локальная проверка не требует подключения к базе данных:

```bash
npm run verify
```

Она проверяет синтаксис основных файлов, порядок регистрации Express-маршрутов,
безопасный запуск PM2-команды и отсутствие журналирования Authorization header.

Существующая команда `npm test` выполняет сетевой сценарий парсера и не является
изолированным набором unit-тестов.

## Текущие ограничения

- `server.js` пока совмещает маршруты, SQL и управление процессами;
- административный API рассчитан на закрытый контур;
- схема базы данных ещё не сведена к единой последовательности миграций;
- покрытие автоматическими тестами начинается со структурных smoke-проверок.

До публикации в открытый контур требуется отдельный production-аудит доступа,
конфигурации reverse proxy, резервного копирования и наблюдаемости.
