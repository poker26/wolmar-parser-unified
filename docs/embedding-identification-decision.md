# Решение по визуальным эмбеддингам монет

Дата решения: 2026-08-28.

## Решение

BioCLIP-эмбеддинги используем как визуальный ранжировщик только внутри списка
типов, которые уже прошли жёсткие структурные ограничения по стране, номиналу и
году. Эмбеддинг не создаёт кандидатов, не заменяет распознавание по двум фото и
не используется как fallback при пустом результате.

Предполагаемый путь запроса:

1. Qwen получает одновременно две стороны и извлекает атрибуты монеты.
2. Каталоговый поиск применяет жёсткие ограничения и возвращает допустимые типы.
3. Если допустимых типов несколько, BioCLIP меняет только их порядок.
4. При недостаточной уверенности порядок каталога сохраняется; при пустом списке
   приложение честно сообщает, что совпадение не найдено.

На первом этапе ранжирование работает в shadow-режиме и не меняет ответ
пользователю. После набора независимой разметки оно может менять порядок
вариантов, но не должно автоматически создавать каталоговую связь.

## Почему не самостоятельный определитель

На дедуплицированном holdout из независимых аукционных фотографий модель дала:

- 64 проверяемых типа из 100;
- top-1: 54/64, или 84,38%;
- top-6: 61/64, или 95,31%;
- медианный ранг правильного типа: 1.

Даже лучший наблюдаемый порог по разнице между первым и вторым местом дал только
96% точности на 78% проверяемых запросов. Для автоматической каталоговой связи
этого недостаточно.

## Какие изображения использовать

В боевой базе 99 483 типа. Парные изображения доступны для 45 795 типов:

- 18 413 типов имеют связанные парные фотографии аукционных лотов;
- 30 247 типов имеют собственные парные изображения в каталоге;
- пересечение приводит к 45 795 уникальным типам с любым источником пары.

Гибридный тест сохранил результат 54/64 на прежних аукционных эталонах, но пять
дополнительных запросов с каталоговым эталоном дали только 2/5 в top-1 и 2/5 в
top-6. Поэтому первый рабочий индекс строится только по аукционным парам.
Каталоговые кропы можно подключать после адаптации модели к разнице между
сканированным каталогом и телефонной фотографией.

## Условия включения в пользовательский ответ

- Полный индекс строится из версионированного manifest с происхождением каждого
  изображения; кэш зависит от URL и источника, а не только от `type_id`.
- Эталонные и тестовые фото разделяются по физическому экземпляру/источнику;
  точные и близкие дубли исключаются до расчёта метрик.
- Shadow-выборка содержит не менее 300 независимо проверенных запросов, включая
  реальные фотографии с телефона и основные эры каталога.
- Измеряется выигрыш относительно порядка без эмбеддингов именно внутри строгого
  списка кандидатов, а не глобальный поиск по случайным типам.
- Порог воздержания выбирается по целевой точности не ниже 99%; отсутствие
  уверенного результата не заменяется ближайшим типом.
- Отдельно проверяются время ответа и стабильность постоянного сервиса. Текущий
  CPU-пилот кодирует 0,77–0,87 изображения в секунду в пакетном режиме; это не
  является измерением latency одиночного пользовательского запроса.

## Когда вернуться к каталоговым изображениям и дообучению

Каталоговые изображения стоит повторно проверять после подготовки пар
«телефонная/аукционная фотография — каталоговый кроп» и обучения адаптера либо
coin-specific модели. Новый тест должен использовать независимые экземпляры,
разные фоны, блики, повороты и износ. До такого теста увеличение числа типов в
индексе за счёт каталоговых кропов считается формальным, а не рабочим покрытием.
