## Контракт по точным типам Биткина — реализован, можно материализовать

1. **Ссылка выбирает точный тип.** `parseTitle` отдаёт `p.bitkin` («Биткин №# 638.147» → `638.147`;
   «Биткин редкость - R» номером не считается). Имперская ветка сначала ищет по
   `coin_type.bitkin_number` с `conf 0.95` и только потом разбирается признаками. Ничья между
   типами с одним номером решается числом уже привязанных лотов.
2. **Точные варианты не размывают общий пул.** В общий отбор имперской эры типы со
   `status='draft'` больше НЕ входят. Материализуйте точные варианты как `draft` — они будут
   достижимы только по явной ссылке, а лоты без ссылки останутся на прежних page-level типах.
3. **Участие по status/source описано в коде** (комментарий «УЧАСТИЕ ТИПОВ В ОТБОРЕ» в матчере).
   Кратко: участвуют все типы независимо от источника; статус означает происхождение, а не
   качество; исключение одно — `draft` вне общего имперского пула. Порядок предпочтения:
   номер Биткина → сюжет из начала заголовка → совпадение темы по словам → двор с инициалами
   минцмейстера → число привязанных лотов → меньший id.
