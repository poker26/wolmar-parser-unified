# Масса и проба в результате распознавания

## Назначение

Распознавание сохраняет буквальные сведения с фотографий отдельно от данных
каталога. Надпись `ONE OUNCE 999 SILVER` описывает физические признаки монеты,
но сама по себе не доказывает точный каталожный тип.

Контракт решает четыре задачи.

1. Он сохраняет исходную надпись и фотографию, на которой она прочитана.
2. Он переводит однозначные единицы в единую систему по проверяемому правилу.
3. Он различает полную массу монеты и массу чистого металла.
4. Он не передаёт оценщику неоднозначные или противоречивые значения.

## Ответ API

Поле `physical_observations` добавляется в `extracted`. Все новые поля
необязательны, поэтому старый мобильный клиент продолжает читать ответ.

```json
{
  "extracted": {
    "metal": "silver",
    "physical_observations": {
      "schema_version": 1,
      "mass": {
        "observations": [],
        "resolved": null,
        "status": "absent",
        "conflicts": []
      },
      "fineness": {
        "observations": [],
        "resolved": null,
        "status": "absent",
        "conflicts": []
      }
    }
  }
}
```

`status` принимает одно из четырёх значений:

- `resolved` означает, что совместимые наблюдения дают одно значение;
- `ambiguous` означает, что надпись прочитана, но её смысл или единица не
  установлены;
- `conflict` означает, что фотографии дают несовместимые значения;
- `absent` означает, что подходящей надписи нет.

## Наблюдение массы

```json
{
  "observation_id": "mass:image-2:one-ounce",
  "source_text": "ONE OUNCE 999 SILVER",
  "image_index": 2,
  "value_text": "ONE",
  "value": "1",
  "source_unit": "troy_ounce",
  "normalized_grams": "31.1034768",
  "normalization_rule": "precious_metal_coin_ounce_v1",
  "mass_role": "unspecified",
  "metal_context": "silver",
  "confidence": 0.99
}
```

Числа передаются десятичными строками. Это исключает зависимость результата от
округления двоичного числа в разных клиентах.

`source_unit` принимает значения `gram`, `troy_ounce` и
`ounce_unspecified`. Правило `precious_metal_coin_ounce_v1` трактует `OUNCE`
или `OZ` как тройскую унцию только тогда, когда та же надпись содержит название
драгоценного металла и пробу либо слово `FINE`. Во всех остальных случаях
единица получает значение `ounce_unspecified`, а `normalized_grams` остаётся
пустым.

Одна тройская унция содержит ровно 480 гранов. При точном значении одного грана
64,79891 мг результат вычисления составляет 31,1034768 г. Сервер выполняет
преобразование, а модель возвращает исходное число и текст. Источник единиц:
[NIST Handbook 44, Appendix C](https://www.nist.gov/document/2026-nist-handbook-44-appendix-c).

`mass_role` принимает значения:

- `gross_mass`, если надпись прямо говорит о полной массе;
- `fine_metal_mass`, если надпись прямо говорит о массе чистого металла;
- `unspecified`, если надпись не объясняет роль массы.

Надпись `ONE OUNCE 999 SILVER` даёт массу 31,1034768 г с ролью
`unspecified`. Система не называет её полной массой или массой чистого серебра
без дополнительного доказательства.

## Наблюдение пробы

```json
{
  "observation_id": "fineness:image-2:999-silver",
  "source_text": "ONE OUNCE 999 SILVER",
  "image_index": 2,
  "value_text": "999",
  "normalized_fraction": "0.999",
  "parts_per_thousand": "999",
  "metal_context": "silver",
  "normalization_rule": "metal_adjacent_fineness_v1",
  "confidence": 0.99
}
```

Число `999` распознаётся как проба только рядом с названием металла или словом
`FINE`. Число `9999` в таком же контексте получает значение `0.9999`, а поле
`parts_per_thousand` получает значение `999.9`. Отдельное число без контекста
не считается пробой.

## Разрешённое значение

Массив `observations` хранит каждое буквальное чтение. Если одна надпись видна
на двух фотографиях, обе записи сохраняются. Проекция `resolved` объединяет
совпадающие записи и перечисляет их идентификаторы в `evidence_observation_ids`.

```json
{
  "status": "resolved",
  "resolved": {
    "normalized_grams": "31.1034768",
    "source_unit": "troy_ounce",
    "mass_role": "unspecified",
    "evidence_observation_ids": ["mass:image-2:one-ounce"]
  },
  "conflicts": []
}
```

Разные однозначные значения переводят поле в состояние `conflict`. Сервер
записывает пары идентификаторов и причину в `conflicts`. Он не выбирает значение
по большей уверенности. Новое распознавание может исправить конфликт, но должно
сохранить прежний ответ в истории доказательств.

## Нормализация надписей

Сервер применяет следующие правила:

| Надпись | Значение | Результат |
| --- | --- | --- |
| `ONE OUNCE 999 SILVER` | одна унция серебра 999 пробы | `31.1034768 g`, роль `unspecified`, проба `0.999` |
| `1 OZ .999 FINE SILVER` | одна унция чистого серебра | `31.1034768 g`, роль `fine_metal_mass`, проба `0.999` |
| `1/2 OZ 999 SILVER` | половина унции серебра 999 пробы | `15.5517384 g`, роль `unspecified`, проба `0.999` |
| `¼ OZ 9999 GOLD` | четверть унции золота 999,9 пробы | `7.7758692 g`, роль `unspecified`, проба `0.9999` |
| `31.1 g` | масса без указанной роли | `31.1 g`, роль `unspecified` |
| `1 OZ` | вид унции не установлен | состояние `ambiguous`, нормализованной массы нет |
| `999` | контекст пробы отсутствует | наблюдение пробы не создаётся |

Десятичная запятая и точка считаются равными. Обыкновенные дроби и символы
`½`, `¼`, `⅕`, `⅒` разбираются в точное рациональное число до перевода в граммы.
Сервер ограничивает допустимые значения справочником единиц и не принимает
произвольную арифметику из ответа модели.

## Передача между компонентами

Модель возвращает `source_text`, `image_index`, исходное число, исходную единицу,
предполагаемую роль и уверенность. Сервер повторно извлекает число из
`source_text`, проверяет контекст и вычисляет нормализованное значение. Ответ с
несогласованным исходным текстом получает состояние `ambiguous`.

Android и iOS добавляют необязательное поле `physicalObservations` в
`IdentifiedFields`. Мобильный клиент сохраняет весь объект в
`IdentificationEvidence`. Поле `MarketIssue.massGrams` продолжает хранить массу
каталожного выпуска и не смешивается с наблюдением на фотографии.

Коллекция хранит ответ как доказательство для конкретного экземпляра. Она не
изменяет `coin_type`, каталожный выпуск или общую карточку монеты.

## Использование в оценке

Если монета связана с точным каталожным типом, оценщик использует проверенные
характеристики выпуска. Наблюдения с фотографии помогают проверить связь и
описать экземпляр.

Расчёт стоимости металла может использовать наблюдение только при выполнении
всех условий:

1. Масса и проба имеют состояние `resolved`.
2. Металл установлен по буквальной надписи или проверенному каталожному типу.
3. Роль массы установлена.
4. Между наблюдением и каталогом нет конфликта.

Для `gross_mass` оценщик умножает массу на пробу. Для `fine_metal_mass` оценщик
использует массу напрямую и не умножает её на пробу повторно. Значение с ролью
`unspecified` не участвует в расчёте стоимости металла.

Рыночная оценка по проходам сохраняет общий механизм оценки по `type_id`.
Физические наблюдения не создают второй прогноз и не подменяют сопоставимые
продажи стоимостью металла.

## Приёмочные проверки

Реализация должна пройти табличные тесты для всех примеров из раздела
нормализации. Отдельные тесты проверяют повторы на двух фотографиях, конфликт
масс, конфликт проб, отсутствие контекста, различие полной массы и массы чистого
металла, а также запрет повторного применения пробы.

Зафиксированный запрос Святой Елены служит регрессионным примером. Ожидаемый
результат содержит массу 31,1034768 г с ролью `unspecified`, пробу `0.999` и
металл `silver`. Эти наблюдения не меняют итог `catalog_match=not_found`.
