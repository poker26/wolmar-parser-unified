**Правила, которые легко сломать заново:**
1. **`\b` в JavaScript не работает с кириллицей.** `/\bбона\b/.test("Бона 5")` = false. Все
   границы слов — через `(?<![а-яё])…(?![а-яё])`. Из-за этого дизамбигуация по монетным дворам
   МОЛЧА не работала: `p.mints` всегда был пуст, хотя код по нему ветвился.
2. **Правка регулярок через python-heredoc роняет в файл управляющие символы** (`\b` → 0x08).
   После каждой такой правки — проверка файла на символы < 0x20, иначе регулярка молча мертва.
3. Зазывалка ставки («С 1 рубля», «От 1 рубля!!!!») и оценка по справочнику («Петров - 1,25
   рубля») — НЕ номинал. Через них в русский модерн затекали Замбия и центы США.
4. Год чеканки — не первое четырёхзначное число: приоритет у года с пометкой «г.», затем вне
   диапазона («1941-1945 гг. 1992г.» — монета 1992-го).
5. Название единицы («рубль», «копеек», «доллар») темой не является: оно есть в имени каждого
   кандидата, и совпадение находилось сразу у всех.
6. Слова о состоянии и отсылки к справочникам («Чеканный блеск», «Петров») попали в НАЗВАНИЯ
   типов, собранных из описаний wolmar. В отборе по теме они не участвуют, иначе лот выбирает
   разновидность вместо тиражного типа.
7. Признаки не-монеты разделены: жёсткие (банкнота, бона, ассигнация, кооперативная бона) — где
   угодно; мягкие (жетон, медаль, марка, вексель) — только в НАЧАЛЕ заголовка, потому что
   «с сертификатом» и «с 1 жетоном» описывают то, что лежит рядом с монетой. «2 марки 1934» —
   номинал, а не почтовая марка.
8. «Лот» сам по себе не набор (это номер лота продавца), «перепутка» — разновидность одной

9. Гейт по металлу: без драг-признака в описании драгоценные кандидаты выкидываются (дешёвый
   тёзка не должен сесть на золотой тип). Для имперской эры и СССР гейт смягчён — там серебро
   норма номинала. Если тема указывает на тип однозначно, гейт уступает.
10. Ничья решается числом уже привязанных лотов: в каталоге есть дубли одного типа из разных

### Прогнозы + автоматическая смена аукциона (2026-08-27, релиз `82246a6`)
**Почему прогнозы молчали с 15.06.** Резолвер текущего аукциона искал ближайший по `auction_end_date` БЕЗ фильтра источника, а с 19.06 в `auction_lots` лежат маркетплейсы (130k строк meshok + auction.ru) с `auction_number IS NULL` и живыми датами. `resolveAuction(null)` возвращал строку `'null'` → `countLots` = 0 → Temporal-воркфлоу завершался мгновенно; в админке это выглядело как «не запускается». Запасная ветка ломалась иначе: `ORDER BY auction_number DESC` по varchar после numismat-префиксов давала `'n99'`.
→ **`utils/current-auction.js`** — единый резолвер (только wolmar, только числовой номер, сортировка ЧИСЛОМ). Подключён в `temporal/activities.js`, `generate-predictions-with-progress.js`, `improved-predictions-generator.js`, `server.getCurrentAuctionNumber`. Крона на прогнозы НИКОГДА не было (проверено: crontab, systemd, node-cron в admin-server — только парсер и неактивен).
Ещё: `PREDICTIONS_PATH` в `admin-server.js` указывал на `/var/www/wolmar-parser` (копия 09.2025) — теперь от `__dirname`.
«Избранное» работало, потому что идёт мимо резолвера (явные lot_id). «Не для всех» — не баг: `no_similar_lots` при отсутствии аналогов В ТОМ ЖЕ грейде (кросс-грейд запрещён), строка есть, `predicted_price` = NULL.
